## Comments and documentation

Write about the code as it stands, in the present tense: what a thing is and what it does.

- Do not describe how the code changed, what it used to do, or the bug that prompted it. A reader
  arriving fresh has no history and needs none.
- Do not define a thing by what it is not or what it avoids. State its behaviour; a negative belongs
  to a real edge case, where the value or the outcome is the point.
